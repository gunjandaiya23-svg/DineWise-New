# How quality is measured

Run `make goldset` to build the silver labels, then `make retrieval-eval` to compare BM25, dense and hybrid retrieval. The review sheet in `data/gold/` is intended for manual inspection.

Labels are generated by a rubric over structured fields and textual evidence. They are silver judgments, not independent human relevance ratings. Regenerate them when the corpus or fixed query suite changes; old scores cannot be compared directly with new labels.

Success@5 asks whether a relevant result occurs in the first five. Precision@5 measures the relevant fraction. MRR rewards an earlier first relevant hit. nDCG@5 rewards highly relevant results near the top. The metrics code reports strict and broader success variants; use the exact JSON field names when explaining a result.

Retrieval compliance checks assess catalogue membership and selected constraints. Answer validation is a separate, limited check on generated text. Workflow fallback counts, generation grounding and retrieval relevance answer different questions.

The query suite has 12 answerable questions and three refusal scenarios. It covers all five cities but remains small. Do not present these scores as broad real-world performance estimates. Bootstrap intervals, RAGAS and NLI validation are not implemented in the current pipeline.
